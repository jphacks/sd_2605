# M5Stack

M5Unifiedを使用するArduinoスケッチです。

- `firmware/m5stack/core/core.ino`: M5GO-CORE1 v2.7（M5Stack Core）のPIR連動音声再生。
- `firmware/m5stack/cores3/cores3.ino`: CoreS3用の既存スケッチ。

## Coreの接続と準備

電源を切ってUnit PIRをGroveケーブルでPORT Bへ接続します。PIR出力はGPIO36です。GPIO36には内部プルアップを設定しません。スピーカーは内蔵のものを使用します。

microSDカードをFAT32でフォーマットし、ルートへ`welcome.wav`を配置してください。対応形式は **WAV / PCM / モノラル / 16bit / 16kHz** です。MP3や浮動小数点WAVには対応しません。例えば「おかえりなさい」の録音をAudacityでこの形式に書き出すか、インストール済みのffmpegがあれば以下で変換できます。

```powershell
ffmpeg -i input.m4a -ac 1 -ar 16000 -c:a pcm_s16le welcome.wav
```

音声素材は別途用意してください。SD未挿入・ファイル欠落・不正形式では`SD ERROR`を表示し、代わりにチャイムを再生します。読み込み途中のエラーでは残りのバッファを再生してから短い代替音を鳴らします。カードを挿し直した場合はAで再試行でき、認識できなければ本体を再起動してください。使用中のカード抜去は避けてください。

必要なライブラリはM5Unifiedと依存するM5GFXです。この環境ではM5Unified 0.2.26 / M5GFX 0.2.33を使用します。SD/SPIはESP32ボードパッケージ付属です。

## コンパイル・書き込み

リポジトリのルートで実行します。

```powershell
arduino-cli compile --fqbn m5stack:esp32:m5stack_core --output-dir .\build\core .\firmware\m5stack\core
arduino-cli upload -p COM5 --fqbn m5stack:esp32:m5stack_core --input-dir .\build\core .\firmware\m5stack\core
```

従来のコンパイルと書き込みを一括実行するコマンドも利用できます。

```powershell
arduino-cli compile -u -p COM5 --fqbn m5stack:esp32:m5stack_core .\firmware\m5stack\core
```

シリアルログは115200 baudです。モニターを閉じてから書き込んでください。

```powershell
arduino-cli monitor -p COM5 --config baudrate=115200
```

## 動作と操作

画面は日本語の案内付きです。緑の「準備OK」になったらセンサーの前を横切ってください。水色は再生中、黄色は再生後の待機またはセンサーのHIGH保持、オレンジは検知です。「反応が続いています」はクールダウン終了後もHIGHのため、センサーから離れてLOWを待つ状態です。検知回数はPIRによる検知だけを数え、Aの音テストでは増えません。

画面下端の表示は本体の左からA・B・Cに対応します。Cで本体上のテスト手順を開閉できます。手順表示中も検知・再生・A/Bの操作は動作します。右上の「音 ON / 消音 ON」で消音状態、下段の「音源」でWAVか代替チャイムかを確認できます。SD ERRORでもチャイムによるテストは可能です。

### はじめてのテスト（SDカードなしでOK）

1. 電源を切ってPIRをPORT Bへ接続し、起動します。右上が「音 ON」であることを確認します。
2. **Aを押します。** 短いチャイムが鳴れば、まずスピーカーの確認は成功です。SDなしのSD ERRORはこのテストでは問題ありません。
3. センサーから離れ、10秒の待機とHIGH保持が終わって、緑の「準備OK」かつ「静止 LOW」になるまで待ちます。
4. **センサーの前を横切ります。** 検知回数が1増え、音が1回鳴り、その後10秒の待機表示になれば成功です。待機中に横切っても回数と再生が増えないことを確認します。
5. 再び離れて「準備OK」を待ち、もう一度横切ります。検知回数が増えて再生されることを確認します。
6. **Bを押して「消音 ON」にし、Aを押します。** 音が出ないことを確認します。もう一度Bを押して音を戻します。
7. 最後に、電源を切って正常形式の`welcome.wav`入りSDを挿して再起動します。「音源: welcome.wav」になり、Aで録音した声が聞こえればWAV再生も成功です。

Aでも音が出ない場合は、右上の消音状態を確認してください。Aでは鳴るのに人感で鳴らない場合は、「準備OK」と「静止 LOW」を確認してから横切り、センサー表示がHIGHに変わるかを見てください。HIGHまたはLOWに固定されて変化しない場合は、電源を切り、PORT Bとケーブルの接続を確認してください。

起動時に短い確認音が1回鳴ります。PIRのLOW→HIGHで検知し、`MOTION DETECTED`を短く表示してから`PLAYING`になります。再生完了後10秒間は`COOLDOWN`です。PIRが約2秒間HIGHを保持しても連続再生しません。再生・クールダウン中の立ち上がりは破棄し、次のLOW→HIGHが必要です。起動時からHIGHの場合も一度LOWになる必要があります。時間経過後もHIGHなら`WAIT LOW`（反応が続いています）表示でLOWを待ちます。

- A: 手動テスト再生。クールダウン中も使用できます。再生中は受け付けません。再生後はクールダウンを最初から開始します。
- B: ミュート切り替え。再生中も即座に音量を0にします。内部の再生処理は進み、解除すると残りが聞こえます。
- ミュート中の検知: 回数に加算し、音を出さず10秒間待機します。状態は再起動で解除されます。

画面には状態、PIRレベル、検知回数、ミュート状態、クールダウン残秒を表示します。SDエラーは状態欄とは別に表示し、次回正常にWAVを開けると消えます。詳細なエラー理由はシリアルへ出力します。

`COOLDOWN_MS`、`DETECT_DISPLAY_MS`、`VOLUME`、`WELCOME_PATH`はスケッチ先頭で変更できます。Unit PIRの感度・出力保持時間そのものはソフトウェアでは変更できません。検知は立ち上がり方式で、保持時間より長いクールダウンを設けています。

WAVは公式[M5Unified Speaker_SD_wav_fileサンプル](https://github.com/m5stack/M5Unified/blob/master/examples/Advanced/Speaker_SD_wav_file/Speaker_SD_wav_file.ino)を参考に、1024バイト×2の固定バッファで逐次読み込みします。オーディオタスクのバッファ解放通知を使い、再生中のメモリを上書きしません。長時間のdelayは使用せず、再生、PIR、ボタン、時間管理をloopから更新します。将来の音声登録は`WELCOME_PATH`と`openWelcome()`のファイル入力部分を起点に追加できます。Wi-Fiやアップロード機能は今回の実装には含みません。

## 実機確認項目

1. 起動音が1回鳴り、READYになること（SDなしではSD ERROR併記）。
2. PIRの前を通過すると検知回数が増え、WAVまたは代替チャイムが1回鳴ること。
3. HIGH保持中に再生を繰り返さず、再生終了後10秒間は検知を受け付けないこと。
4. LOWへ戻った後、クールダウン終了後の次の立ち上がりで再生できること。
5. Aで再生でき、連打しても音声が重複しないこと。
6. Bでミュート表示と消音・解除が動作すること。
7. SDなし、ファイルなし、不正WAVでエラー表示と代替音が動作すること。
8. 正常WAVで音声が途切れず、再生開始・終了とPIR変化が115200 baudで記録されること。

コンパイル・書き込みの成否と、上記の実機検証結果は別々に確認してください。
